
Relational Operator Replacement

The relational operator replacement operator will invert conditional operators in your code based on this table:

+-------------------+------------------+
| Original Operator | Changed Operator |
+-------------------+------------------+
|        ==         |        !=       |
+-------------------+-----------------+
|        !=         |        ==       |
+-------------------+-----------------+
|        >=         |        <=       |
+-------------------+-----------------+
|        <=         |        >=       |
+-------------------+-----------------+
|        >          |        <        |
+-------------------+-----------------+
|        <          |        >        |
+-------------------+-----------------+


The purpose of this operator is to highlight how your tests respond to changes in branching logic.
A well-engineered test suite will be able to fail clearly in response to code taking a different branch than it expected.

Mutating an equality check

if myValue == 50 {
    // something happens here
}

becomes

if myValue != 50 {
    // something happens here
}


Relational Boundary

The relational boundary operator will move the boundary of an ordering comparison based on this table:

+-------------------+------------------+
| Original Operator | Changed Operator |
+-------------------+------------------+
|         <         |        <=        |
|        <=         |         <        |
|         >         |        >=        |
|        >=         |         >        |
+-------------------+------------------+

The purpose of this operator is to highlight whether your tests check the edge of each comparison.
Such a mutant survives unless some test uses the value at the boundary, where the two operators differ.

Mutating a boundary

if count < 10 {
    // something happens here
}

becomes

if count <= 10 {
    // something happens here
}


Remove Side Effects

The remove side effects operator will remove code it determines is causing a side effect.
It will determine your code is causing a side effect based on a few rules:
    • A line contains a function call which is explicitly discarding a return result.
    • A line contains a function call and doesn't save the result of the function call into a named variable or constant (i.e. a line implicitly discards a return result or doesn't produce one).
    • A line does not contain a call to print, exit, fatalError, preconditionFailure, abort, or any function listed in muter.conf.yml under the excludeCalls key.
The purpose of this operator is to highlight how your tests respond to the absence of expected side effects.

Mutating an explicitly discarded return result

func initialize() {
    _ = self.view
    view.results = self.results
}

becomes

func initialize() {
    view.results = self.results
}

Mutating a void function call

func update(email: String, for userId: String {
    var userRecord = record(for: userId)
    userRecord.email = email
    database.persist(userRecord)
}

becomes

func update(email: String, for userId: String {
    var userRecord = record(for: userId)
    userRecord.email = email
}


Change Logical Connector

The change logical connector operator will change conditional operators in your code based on this table:

+-------------------+------------------+
| Original Operator | Changed Operator |
+-------------------+------------------+
|         &&        |        ||        |
+-------------------+------------------+
|         ||        |        &&        |
+-------------------+------------------+

The purpose of this operator is to highlight how your tests respond to changes in logic.
A well-engineered test suite will be able to fail clearly in response to different logical constraints.

Mutating a Logical AND

func isValidPassword(_ text: String, _ repeatedText: String -> Bool {
    let meetsMinimumLength = text.count >= 8
    let passwordsMatch = repeatedText == text
    return meetsMinimumLength && passwordsMatch
}

becomes

func isValidPassword(_ text: String, _ repeatedText: String -> Bool {
    let meetsMinimumLength = text.count >= 8
    let passwordsMatch = repeatedText == text
    return meetsMinimumLength || passwordsMatch
}



Swap Ternary

The swap ternary operator will swap ternary operators in your code based on this table:

+---------------------------------------------+---------------------------------------------+
|              Original Operator              |               Changed Operator              |
+---------------------------------------------+---------------------------------------------+
| <condition> ? <expression1> : <expression2> | <condition> ? <expression2> : <expression1> |
+---------------------------------------------+---------------------------------------------+

The purpose of this operator is to highlight how your tests respond to changes in logic.
A well-engineered test suite will be able to fail clearly in response to different logical constraints.

Mutating a ternary expression

func stringify(_ a: Bool -> String {
    return a ? "true" : "false"
}

becomes

func stringify(_ a: Bool -> String {
    return a ? "false" : "true"
}



Negate Conditional

The negate conditional operator will wrap each expression condition of an if, guard or while in !( ).
Conditions that aren't expressions, such as if let, case and #available, are left alone, and so are the literals true and false.
While the relational operator replacement operator is on, so is a condition that is one == or != comparison, which that operator already negates.

The purpose of this operator is to highlight whether your tests tell the two branches apart.
A negated while condition can loop until the mutant's time limit, which counts as a survivor.

Mutating a condition

if isValid && !isEmpty {
    // something happens here
}

becomes

if !(isValid && !isEmpty) {
    // something happens here
}


Change Arithmetic Operator

This operator will change arithmetic operators in your code based on this table:

+-------------------+------------------+
| Original Operator | Changed Operator |
+-------------------+------------------+
|         +         |         -        |
|         -         |         +        |
|         *         |         /        |
|         /         |         *        |
|         %         |         *        |
|        +=         |        -=        |
|        -=         |        +=        |
|        *=         |        /=        |
|        /=         |        *=        |
|        %=         |        *=        |
+-------------------+------------------+

+ and += also join strings and arrays, so they change only with a sign of numbers beside them: a numeric literal, a name such as items.count, or an arithmetic operator other than those two.
One that changes nothing, as in x * 1, is left alone.

The purpose of this operator is to highlight whether your tests check the value a calculation gives.

Mutating a calculation

let next = index + 1

becomes

let next = index - 1


Flip Boolean Literal

The flip boolean literal operator will turn true into false and false into true.
A literal that is a whole condition, as in while true, or in a pattern, as in case true:, is left alone, as a flipped one often doesn't compile.

The purpose of this operator is to highlight whether your tests check the values your code gives and is given.

Mutating a literal

return true

becomes

return false


Replace Boolean Value

The replace boolean value operator will replace a Bool value with true, and in a second mutant with false.
A value is what a return gives, the one expression of a body that returns it, or the initial value of a let or var.
It counts when its type is written as Bool, or when it is a comparison, &&, || or !.
A literal, an if or switch expression, and a closure that doesn't write its return type are left alone.

The purpose of this operator is to highlight whether your tests see a value both true and false.

Mutating a value

return items.isEmpty

becomes

return true

and

return false
