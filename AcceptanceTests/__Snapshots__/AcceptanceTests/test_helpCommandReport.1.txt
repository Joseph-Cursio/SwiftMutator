OVERVIEW: Builds a report from a run's results file, or from its shards'
results files merged.

USAGE: swift-mutator report [<options>] <results> ...

ARGUMENTS:
  <results>               A run's results file, or the log folder in
                          <project>_muter_logs of any of the run's sessions.
                          Several, one for each shard of a run --shard split,
                          are merged into one report.

OPTIONS:
  -f, --format <format>   The report format: plain, json, html, xcode,
                          markdown, stryker, sarif
  -o, --output <output>   Output file for the report to be saved.
  --report <format:path>  Also save a report in another format, as format:path,
                          such as markdown:summary.md. Repeatable. For a run,
                          in place of reports.
  --fail-under <percent>  Exit with status 2 when the headline mutation score,
                          counting any mutant taken out of the build with
                          others as not killed, is below this percent, from 0
                          to 100, or every mutant was a build error, once the
                          report is written. For a run, in place of failUnder.
  --baseline <path>       Compare the survivors with those of this baseline
                          file, which --write-baseline saved, and exit with
                          status 2 when more are new than --max-new-survivors
                          allows, once the report is written. Only the mutants
                          tested are compared. Exit with status 8 if the file
                          can't be read, or records another scope: other
                          operators, or another configuration.
  --max-new-survivors <count>
                          With --baseline, how many new survivors pass: a whole
                          number, 0 or more. 0 when not given.
  --max-score-drop <points>
                          With --baseline, exit with status 2 when the score,
                          counted as --fail-under counts it, is more than this
                          many points below the baseline file's, from 0 to 100,
                          once the report is written. Flaky tests alone move
                          the score a point or two between runs, so 0 fails at
                          random. Only a whole run's score is compared.
  --max-doubtful-kills <count>
                          Exit with status 2 when more kills than this whole
                          number are doubtful, once the report is written:
                          those only suspect tests made that no rerun alone
                          settled, and those whose code never ran.
  --write-baseline <path> Save the survivors to a baseline file at this path,
                          such as muter.baseline.yml, for --baseline to compare
                          later runs with. Only a whole run's results make one.
                          It may be --baseline's own file, which is read first.
  --property-tests <glob> Split the report's kills between example tests and
                          the property tests this glob matches by name or by
                          the file their issue was recorded in; * matches any
                          characters. Repeatable. In place of propertyTests.
  --force-merge           Merge shards' results although their SwiftMutator
                          build, toolchain or SDK differ. With one file, it
                          does nothing.
  --merge-ignoring <glob> Merge shards' results although project files matching
                          this glob differ between them; * also matches /.
                          Repeatable. With one file, it does nothing.
  --summary <path>        Also save the run's summary.json, its score, counts
                          and details for scripts, at this path.
  --triage <path>         Show the labels in this triage file, if not
                          muter.triage.yml in the run's project, or in the
                          current folder.
  --version               Show the version.
  -h, --help              Show help information.
