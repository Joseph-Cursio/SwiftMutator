# Measured: `run --reuse`

On 31 October 2026, for [#71](https://github.com/Joseph-Cursio/SwiftMutator/issues/71), SwiftProjectLint's whole repo was run four times, to see what `run --reuse` saves and whether the results it keeps are the ones a full run would give. Each scenario ran once, so read the times as indicative.

## Summary

- **With nothing changed, the reuse took 4.2 min against 27.3 min for the full run.** It kept 2,454 of the 2,463 results and tested the 9 timeouts again, which took most of its time; the baseline took 38 s.
- **After one test file changed, it took 19.0 min against 26.6 min for a full run of the same change, 29% less.** It kept 1,816 results and tested 647 again: the 9 timeouts, all 578 survivors, and 60 of the 1,876 kills.
  - 18 of the 60 kills were by tests in the changed file. 35 were crashes or exits, which name no killing test, and 7 were by tests in files whose names two test folders share, `ProjectLinterTests.swift` and `NetworkingVisitorTests.swift`.
  - The survivors are most of the cost: a survivor runs the whole suite, so in the base run they took 72% of the time spent on kills and survivors.
- **Every kept result matched the full run.** All 1,816 that the reuse after the change kept, and all 2,454 that the reuse with nothing changed kept, had the full runs' verdicts.
- **Only 4 verdicts differed across the runs, all of them retested ones,** and they are the 4 mutants that SwiftProjectLint's tests kill only when they walk a dictionary in one order ([release-and-workers-2026-10.md](release-and-workers-2026-10.md)): `PrimitiveNamedForDomainTypeVisitor.swift:77` and `:105`, and `ContextSymbolTable.swift:96` and `:98`. The base and full runs differed in 3 of them by themselves.

## Setup

| | |
|---|---|
| Machine | Apple M5 Pro, 6 performance and 12 efficiency cores, 64 GB, macOS 27.2, Xcode 27.2 (Swift 6.4.2). |
| SwiftMutator | A release build (`swift build -c release --product swift-mutator`) of `85dc25f2`, the first commit of the `--reuse` branch. The review's fixes came after it. In the scenario measured they change only what counts as a test file: a Swift file under a test folder must now import Testing or XCTest. The measured binary was kept for all four runs: a rebuilt one has another SHA-256, and the reuses would then need `--force-reuse`. |
| Project | The clone of SwiftProjectLint at `c2082e5d` that [release-and-workers-2026-10.md](release-and-workers-2026-10.md) used, in a scratch folder, with the same resolved packages. |
| Configuration | `executable: /usr/bin/swift`, `arguments: [test]`, `mutationTestWorkers: 4`, and the excludes `**/BuiltInRules.swift` and `**/PatternCategory.swift`. |
| Command | `swift-mutator run --skip-coverage --skip-update-check`, from the clone, with `--reuse` of the base run's results file for the two reuses. |
| Change | A new test, `@Test func reuseMeasurementAddedTest() { #expect(Bool(true)) }`, appended to `Tests/CoreTests/Testability/ComparatorNameTests.swift`: of the test files whose names are unique, the one the most kills' killing tests were in. It kills nothing, so a correct reuse keeps what the full run gives. |
| Runs | One after another: base, a reuse with nothing changed, the change, a reuse of the base run, and a full run with the change, after which the file was restored. Each started only once the 1-minute load average was under 4. The CPU used by processes outside the clone averaged 50–115% of a core during the runs. |

## Results

| Run | Whole run | Baseline | Kept | Tested | Killed | Survived | Timed out |
|---|---|---|---|---|---|---|---|
| Base | 27.3 min | 43 s | – | 2,463 | 1,876 | 578 | 9 |
| Reuse, nothing changed | 4.2 min | 38 s | 2,454 | 9 | – | – | 9 |
| Reuse, test file changed | 19.0 min | 36 s | 1,816 | 647 | 62 | 576 | 9 |
| Full, test file changed | 26.6 min | 38 s | – | 2,463 | 1,879 | 575 | 9 |

The Killed, Survived and Timed out columns count the mutants each run tested. With its kept results, the reuse after the change had 1,878 kills, 576 survivors and 9 timeouts, against the full run's 1,879, 575 and 9; the difference is `ContextSymbolTable.swift:96` and `:98`, which each run called the other way.
